## 機能

`wayfinder` は、1回のエージェントセッションでは扱いきれないほど大きな取り組み――まだ先が見通せず、現在地から目標地点までの道筋が見えていないもの――を、課題（issue）管理システム上の **意思決定チケット** の **共有マップ** として整理し、その道筋が明確になるまで1つずつ解決していきます。これは **計画を立てるためのものであり、実装を行うものではありません**。すべてのチケットは1つの意思決定、つまり解決すべき問いを扱い、実装作業そのものを扱うことはありません。マップは、実際に構築作業を始める前に決めるべきことがなくなった時点で完成となります。つまり、成果物ではなく意思決定を生み出します。

## この機能を使うタイミング

このスキルは `/wayfinder` と入力して呼び出します。エージェントが自動的に利用することはありません。

取り組みが **1回のエージェントセッションでは扱いきれない規模** であり、その **目的地（destination）** への道筋がまだ不明瞭な場合に利用してください。やるべきことの輪郭は見えているが、まだ仕様や計画として書き起こせないような場合です。すでに明確になっている内容を仕様へ落とし込む場合は [to-spec](https://aihero.dev/skills-to-spec) を利用してください。すでに理解できている計画を実装可能なチケットへ分割する場合は [to-tickets](https://aihero.dev/skills-to-tickets) を利用してください。Wayfinder はその両方の上流に位置し、仕様化するにはまだ不確定要素が多すぎるときに使うものです。

## 前提条件

マップとチケットはリポジトリの課題（issue）管理システム上に配置されるため、wayfinder は [setup-matt-pocock-skills](https://aihero.dev/skills-setup-matt-pocock-skills) が設定する課題（issue）管理システム連携を必要とします。この設定には「Wayfinding operations」セクションが含まれ、GitHub、GitLab、またはローカル Markdown において、マップ、子チケット、依存関係、フロンティアクエリをどのように表現するかが定義されています。この設定が存在しない場合、wayfinder はローカル Markdown ベースのマップを既定として使用します。

## マップは索引、霧はフロンティア

**マップ（map）** は単一の `wayfinder:map` issue であり、その子 issue がチケットになります。チーム全体が参照できる1つの共有 URL です。

マップは **情報の保管場所ではなく索引** です。各意思決定は必ず1つのチケットだけに存在し、マップには要約とリンクのみが記載され、内容を重複して保持しません。セッションはまずマップを粗い解像度で読み込み、必要に応じて個々のチケットへズームインします。

進行中のチケットの先には **戦場の霧（fog of war）** があります。つまり、将来的に必要になることは分かるが、まだ具体化できていない意思決定です。ある項目がチケットになるか、それともまだ霧の中にあるかを判断する基準は、「今その問いを正確に定義できるかどうか」であり、「答えを知っているかどうか」ではありません。チケットを解決すると、その先の霧が晴れ、新たに具体化できる内容が新しいチケットとして **昇格（graduate）** します。

**フロンティア** は、未解決かつ依存関係に阻まれておらず、誰にも担当されていないチケット群です。つまり、既知領域の最前線です。これは課題（issue）管理システムの依存関係表示によって可視化されるため、マップを開かなくても着手可能な作業が分かります。

霧は常に **目的地（destination）** に向かう方向にのみ存在します。その先の作業は **範囲外（out of scope）** とされ、クローズされ、チケットへ昇格することもありません。

すべてのチケットは **HITL**（human in the loop：grilling や prototype を含む、人間との対話が必要なもの）または **AFK**（agent alone：research のようにエージェント単独で進められるもの）に分類されます。HITL チケットは実際の対話によってのみ解決されるため、エージェントが自分で質問して自分で答えることはありません。

調査タスクは依然として正式なチケットです。後続の意思決定が依存する共有ブロッカーです。しかし AFK に分類されるため、セッションは停止して調査結果を読むことなく、並列で `/research` サブエージェントを起動してそのチケットを処理し、フロンティアの進行を止めません。調査結果は使い捨ての `research/<name>` ブランチへ保存されます。

## 正常に機能している場合

- チケット作成前にまず **目的地（destination）** を定義すること。すべてのチケットの範囲判断基準となるためです。
- 1つのマップは1つの `wayfinder:map` issue であり、チケットはその子 issue として表現されること。参照には単なる `#42` ではなく**チケット名**を用いること。
- 1回のセッションで解決されるチケットは **最大1件** であること（research チケットは除く）。回答は解決コメントとして記録され、チケットはクローズされ、*Decisions so far* に1行の参照が追加されること。
- 開始時のグリルで **霧が存在しない** と判明した場合は停止し、その作業はマップを作る必要がないほど小規模であると伝えること。

## この機能の位置付け

`wayfinder` は、大規模で不明確な取り組みをメイン開発フローへ接続するための **オンランプ（導入経路）** です。1回で仕様化できないほど大きく霧に包まれた取り組みを、整理された意思決定マップへ変換し、その後メインフローへ合流させます。

霧が晴れ、進むべき道筋が明確になったら、[to-spec](https://aihero.dev/skills-to-spec) へ引き渡して複数セッションにまたがる開発計画を作成します（あるいは、作業規模が小さいと判明した場合は直接実装に進みます）。

このスキルは、個々のチケットを解決するために [grilling](https://aihero.dev/skills-grilling) および [domain-modeling](https://aihero.dev/skills-domain-modeling) を利用し、必要に応じて [prototype](https://aihero.dev/skills-prototype) や [research](https://aihero.dev/skills-research) を使用します。どのスキルやフローを利用すべきかわからない場合は、[ask-matt](https://aihero.dev/skills-ask-matt) が案内します。
