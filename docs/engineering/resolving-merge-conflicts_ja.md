## 機能

`resolving-merge-conflicts` は、進行中の git マージまたはリベース時の競合を、ハンクごとに処理し、解決・検証・コミットまで完了させます。

このスキルはテキストではなく **意図** に基づいて競合を解決します。ハンクに手を加える前に、それぞれの変更をその **一次情報源**（コミットメッセージ、PR、元の issue など）までたどり、なぜその変更が行われたのかを理解した上で、両方の意図が両立可能であれば保持します。競合をごまかすために新しい振る舞いを作り出すことはなく、また `--abort` を使用することもありません。マージは必ず完了させます。

## この機能を使うタイミング

`/resolving-merge-conflicts` と入力するか、タスク内容が適している場合はエージェントが自動的に利用します。

Git が自動解決できない競合によってマージやリベースが途中で停止したときに利用してください。このスキルが対象とするのは目の前の競合そのものです。マージの計画や、その後に発生した不具合の調査には使用しません。マージは完了したものの、その後で原因不明の問題が発生している場合は、代わりに [diagnosing-bugs](https://aihero.dev/skills-diagnosing-bugs) を利用してください。

## 意図による解決

競合で陥りやすい罠は、それを単なるテキスト上の問題として扱い、「ours」または「theirs」を選んで競合マーカーを消してしまうことです。このスキルは競合を **意図の問題** として扱います。ハンクの各側には、それぞれ誰かの目的があります。解決結果は可能な限りその両方の目的を満たす必要があります。もし本当に両立できない場合は、マージの目的により適した方を選び、そのトレードオフを明示します。

そのため、一次情報源が重要になります。読んでいない意図を保持することはできないため、この作業は差分ではなく履歴──コミット、PR、チケット──から始まります。

## 正常に機能している場合

- 解決された各ハンクが両側の振る舞いを保持しているか、保持できない場合はそのトレードオフが明示されていること。
- どちらのブランチにも存在しなかった新しい振る舞いが追加されていないこと。
- プロジェクトの検証手段（型チェック、テスト、フォーマット）が特定され、すべて成功してからコミットされること。
- マージまたはリベースが最後のコミットまで完了し、中止されないこと。

## この機能の位置付け

必要なときにいつでも利用できる**スタンドアロン型スキル**です。マージまたはリベースが停止した時点で呼び出し、解決済みでコミット済みのクリーンな作業ツリーを返します。

最も近い関連スキルは [diagnosing-bugs](https://aihero.dev/skills-diagnosing-bugs) です。競合自体は解消されたものの、その後で期待通りに動作しない場合、それは競合の問題ではなく診断の問題だからです。どのスキルを使うべきかわからない場合は、[ask-matt](https://aihero.dev/skills-ask-matt) が案内します。
