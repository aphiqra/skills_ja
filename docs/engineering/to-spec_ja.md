
```bash
npx skills update to-spec
```

[Source](https://github.com/mattpocock/skills/tree/main/skills/engineering/to-spec)

## 機能

`to-spec` は、現在の会話内容とコードベースへの理解を仕様書（PRD と呼ばれることもあります）へ変換し、それを課題（issue）管理システムへ公開します。

このスキルは **再度インタビューを行いません**。このスキルを利用する段階では、認識合わせの作業はすでに完了しています。`to-spec` は新たな質問を行うのではなく、すでに分かっている内容を統合して仕様化します。

## この機能を使うタイミング

このスキルは `/to-spec` と入力して呼び出します。エージェントが自動的に利用することはありません。

変更内容について十分に議論され、ドメイン言語も確立されており、コードを書く前にその共通理解を文書化したい場合に利用してください。まだ認識合わせが終わっていない場合は、まずグリル（深掘り）を行ってください。そのためには [grill-with-docs](https://aihero.dev/skills-grill-with-docs) を利用します。完成した仕様をチケットへ分割するには [to-tickets](https://aihero.dev/skills-to-tickets) を利用してください。

## 前提条件

`to-spec` は課題（issue）管理システムへ仕様を公開するため、このリポジトリでは事前に [setup-matt-pocock-skills](https://aihero.dev/skills-setup-matt-pocock-skills) によって課題（issue）管理システムとトリアージラベルが設定されている必要があります。このスキルは自ら `ready-for-agent` ラベルを適用するため、別途トリアージ工程を実行する必要はありません。

## 仕様に含まれる内容

- **問題の説明** — 何が壊れているのか、何が不足しているのか、そしてなぜ解決する価値があるのかを、プロジェクト固有の言葉で説明します。
- **解決策** — 実装詳細に入る前の段階で、修正や変更の全体像を示します。
- **ユーザーストーリー** — 変更が満たすべき具体的な振る舞いを網羅的かつ番号付きで列挙します。それぞれ独立して検証可能です。
- **実装上の決定事項** — 会話中にすでに確定した選択事項を記録し、後から再議論されることを防ぎます。
- **テスト方針** — 機能をどの境界（seam）でテストするか、および「完了」と見なす条件を明確にします。
- **対象外項目** — この変更で意図的に扱わない内容を明示し、チケットの範囲を適切に保ちます。
- **補足事項** — 上記のセクションには収まらないが、引き継ぐ価値のある情報を記載します。

## 深いモジュール

仕様を書く前に、`to-spec` は機能をテストするための **境界（seam）** を整理し、**深いモジュール（deep module）** の機会を探します。深いモジュールとは、小さく安定したインターフェースの背後に多くの機能を隠すモジュールです。

このスキルは、新しい境界（seam）を作るよりも既存の境界（seam）を優先し、可能な限り高いレベルの境界（seam）を選択します。理想的には、変更全体に対して 1 つの境界（seam）で済ませることを目指します。

これはエージェント主体の開発において重要です。良いインターフェースはテストの安定した対象となるため、その下の実装コードが変わってもテストを変更する必要がなくなります。

## 正常に機能している場合

- 新しい質問を始めるのではなく、すぐに仕様書の作成を開始すること。
- 仕様を書く前に境界（seam）について確認し、可能な限り少数の境界（seam）を提案すること。
- 仕様が一般的なテンプレートではなく、プロジェクト固有のドメイン言語で書かれていること。

## この機能の位置付け

`to-spec` は、メイン開発チェーンの一工程です。

```txt
grill-with-docs → to-spec → to-tickets → implement → code-review
```

計画とドメイン言語が確定した後、そして実装用チケットへ分割する前に利用してください。

主要な関連スキルは [grill-with-docs](https://aihero.dev/skills-grill-with-docs) で、仕様を正確なものにするためにコンテキストを洗練します。また [to-tickets](https://aihero.dev/skills-to-tickets) は、仕様を [implement](https://aihero.dev/skills-implement) が実装できるチケット群へ変換します。どのスキルやフローを利用すべきかわからない場合は、[ask-matt](https://aihero.dev/skills-ask-matt) が案内します。
