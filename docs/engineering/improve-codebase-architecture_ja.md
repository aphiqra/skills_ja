## 機能

`improve-codebase-architecture` は、コードベースをスキャンして **深さを増す機会（deepening opportunities）** を探します。つまり、浅いモジュール（隠しているものとほぼ同じ複雑さのインターフェースを持つモジュール）を、より深いモジュールにできる箇所を特定し、それらを独立した視覚的な HTML レポートとして提示した後、選択した候補についてグリル形式で掘り下げていきます。

このスキルは **単なるリファクタリング候補の一覧を提示するものではありません**。すべての候補は **deletion test** を通過する必要があります。つまり、そのモジュールを削除した場合に複雑さがより小さなインターフェースの背後へ**集約される**のか、それとも単に別の場所へ移動するだけなのかを確認します。複雑さを集約できる場合のみ、それは候補として採用されます。このフィルターによって、レポートがありふれたコード整理の提案集になることを防いでいます。

特定の領域を指定しない限り、このスキルは実際に開発が行われている場所を重点的に調査します。最近のコミット履歴を読み取り、現在も変更が続いているコードへ重点を置きます。モジュールの深さを増すことの価値は、その部分に対する今後の変更を容易にすることにあるため、最近変更された領域ほど高く評価されます。

## この機能を使うタイミング

このスキルは `/improve-codebase-architecture` と入力して呼び出します。エージェントが自動的に利用することはありません。

定期的な健全性チェックとして利用してください。数日ごと、あるいはコードベースの理解にあたって多数の小さなモジュールを行き来しなければならなくなったと感じたときが目安です。このスキルは既存アーキテクチャを分析し、どこをより深い構造にできるかを提案します。もし再設計したいモジュールがすでに分かっていて、それについて考えるための設計語彙だけが欲しいのであれば、代わりに [codebase-design](https://aihero.dev/skills-codebase-design) を利用してください。このスキルは候補を発見するための調査役であり、`codebase-design` は設計を行うための場です。

## 深さを増す機会

このスキル全体は **深さ（depth）** という考え方に基づいています。深いモジュールは、小さく安定したインターフェースの背後に多くの機能を隠します。一方、浅いモジュールは、その下にある実装とほぼ同じ幅のインターフェースを持ち、内部実装を漏らしています。

レポートはそのような浅さを探します。たとえば、実際の不具合が呼び出し方法にあるにもかかわらずテストしやすさだけを目的に切り出された純粋関数（**locality** の欠如）、**境界（seam）** を越えて責務が漏れているモジュール、ある概念を理解するために 5 つものファイルを開かなければならない状況などです。そして、それらを解消するためにどのような深いモジュール化を行うべきかを提案します。

このスキルは共有された設計語彙（**module**、**interface**、**depth**、**seam**、**adapter**、**leverage**、**locality**）と、`CONTEXT.md` に記録されたプロジェクト固有のドメイン言語の両方を使用します。そのため、候補は「`FooBarHandler` をリファクタリングする」ではなく、「注文受付モジュールを深くする」のように表現されます。

## レポート、その後にグリル

出力はブラウザーで閲覧できる HTML ファイルであり、OS の一時ディレクトリへ書き出されます。リポジトリ内には何も保存されません。各候補はカード形式で表示され、関係するファイル、現在の問題点、平易な言葉での改善案、`locality` と `leverage` の観点での利点、変更前後の図、および `Strong` / `Worth exploring` / `Speculative` の評価が含まれます。最後に、このスキルが最優先で取り組むべきと考える候補が示されます。

その後、スキルは停止し、どの候補をさらに検討したいかを尋ねます。候補を選択すると、その設計について [grilling](https://aihero.dev/skills-grilling) のループを実行します。制約条件、境界（seam）の背後に置くべきもの、どのテストを維持するかなどを順番に整理し、意思決定が固まるたびにドメインモデルも更新していきます。

## この機能の位置付け

`improve-codebase-architecture` は **定期的なメンテナンス** のためのスキルです。チェーンの一工程としてではなく、数日ごとに実行することを想定しています。

近い関連スキルとして、すべての候補が依拠する深さと境界（seam）の設計語彙を提供する [codebase-design](https://aihero.dev/skills-codebase-design)、候補選択後に意思決定ツリーをたどる [grilling](https://aihero.dev/skills-grilling)、そして再設計が固まるにつれて `CONTEXT.md` や ADR を更新する [domain-modeling](https://aihero.dev/skills-domain-modeling) があります。どのスキルやフローを利用すべきかわからない場合は、[ask-matt](https://aihero.dev/skills-ask-matt) が案内します。
