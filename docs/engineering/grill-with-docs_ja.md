## 機能

`grill-with-docs` は、計画や設計について、あなたとエージェントが共通理解に到達するまで、一度に 1 つの質問をしながら徹底的にインタビューを行います。そして、その過程で用語や意思決定を記録します。

このグリル（徹底的な問いかけ）は **記録を残します**。通常のインタビューは思考を整理する助けになりますが、セッション終了とともに消えてしまいます。一方、このスキルは各用語が確定した瞬間に `CONTEXT.md` の用語集へ記録し、重要で後戻りしにくい意思決定を ADR として保存します。そのため、認識合わせの結果は会話が終わった後も残り、頭の中だけに存在する状態になりません。

## この機能を使うタイミング

これは `/grill-with-docs` と入力して呼び出します。エージェントが自動的に利用することはありません。

変更作業のごく初期段階、まだ計画が曖昧でドメイン言語も定まっておらず、コードを書く前にその両方を検証したい場合に利用してください。インタビューだけが必要で成果物が不要な場合は [grilling](https://aihero.dev/skills-grilling) を使用してください。計画はすでに明確で、用語の定義や記録だけが必要な場合は [domain-modeling](https://aihero.dev/skills-domain-modeling) を使用してください。また、変更が大規模すぎて 1 回のセッションでは扱えず、進むべき方向もまだ不透明な場合（新規プロジェクトや巨大な機能開発など）は、まず上流工程の [wayfinder](https://aihero.dev/skills-wayfinder) から始めてください。これにより作業全体が意思決定の地図として整理され、その後メインフローであるこのスキルへ戻ってきます。

## 前提条件

このスキルは状態を持ちます。グリルを進めながらリポジトリへ書き込みを行います。確定した用語はルートの `CONTEXT.md` 用語集に保存されます（`CONTEXT-MAP.md` が存在するマルチコンテキストリポジトリでは、対応するコンテキストの `CONTEXT.md` に保存されます）。本当に後戻りしにくい意思決定は `docs/adr/` 配下の ADR として保存されます。どちらも必要になった時点で初めて作成されるため、事前準備は不要ですが、これらのファイルを書き込んでも安全な場所で実行する必要があります。

## グリル

このスキルのエンジンは **grill** です。意思決定ツリーを一度に 1 問ずつたどり、先に依存関係を解決してから次へ進みます。また、すべての質問に対して推奨回答も提示します。コードベースから答えられる質問については、ユーザーに聞くのではなくコードベースを調査して答えます。

この派生スキル独自の特徴は、回答の保存先にあります。グリルが進行する中で、曖昧な表現は正式な用語へと整理され、その場で用語集に記録されます。最後にまとめて記録するわけではありません。用語集は常に用語集として維持され、実装詳細や仕様書の内容は含みません。ADR は慎重に作成されます。意思決定が後戻りしにくく、背景を知らないと意外であり、かつ実際のトレードオフの結果である場合にのみ提案されます。ほとんどのセッションでは用語集が洗練され、ADR はほとんど、あるいは全く作成されません。それが本来の姿です。

## 正常に機能している場合

- 質問票を一度に並べるのではなく、1 回に 1 つの質問を行い、回答を待つこと。(ver 1.2で変更予定)
- 用語が確定した瞬間に、プロジェクト固有の言葉で `CONTEXT.md` に記録されること。
- 答えられる場合は、コードベースを参照して自らの質問に回答すること。
- ADR はまれであり、簡単に変更できる選択肢に対して形式的な承認を求めないこと。

## この機能の位置付け

`grill-with-docs` は、メイン開発チェーンの開始ステップです。

```txt
grill-with-docs → to-spec → to-tickets → implement → code-review
```

このスキルは、仕様書が作成される前の最初の工程です。ここで共有理解と確立された用語を作り上げ、その結果を [to-spec](https://aihero.dev/skills-to-spec) が再度インタビューすることなく仕様へ変換します。近い関連スキルは、ドキュメント作成機能を持たない同じインタビュー手法の [grilling](https://aihero.dev/skills-grilling) と、このスキルが利用する用語集および ADR 管理の仕組みである [domain-modeling](https://aihero.dev/skills-domain-modeling) です。どのスキルやフローを利用すべきかわからない場合は、[ask-matt](https://aihero.dev/skills-ask-matt) が案内します。
